| Fase | Estado |
|---|---|
| 0 — Validación (DIN-4) | ✅ Done: quotes mainnet reales + firma devnet vía Phantom MCP |
| 1 — MVP v0.1.0 Track A paper | ✅ Done: PR #4 (MVP: usuarios, paper wallets, quotes Jupiter en vivo, gate, simulación real, portfolio, historial) + PR #7 (Terminal amable: diseño implementado en la web real) + PR #8 (deploy Azure + branding Onda). | 1.1 — Updates en vivo + camino a ejecución real | 🔨 SSE habilitado en el preview desde v0.6.0: `GET /api/v1/events` con sesión web — ticks de precios Jupiter cada 12 s sobre el cache de 60 s existente, estados de confirmation solo para su dueño (`pending→executed/rejected/expired/superseded`), señal de portfolio tras ejecutar (la UI refetchea el snapshot autoritativo), heartbeat, reconexión con backoff y fallback al refresh de 30 s; el MCP sigue con polling (Q-M4). Falta para cerrar la fase: ejecución real detrás de `EXECUTION_ENABLED` sigue pendiente de la decisión de fondeo del operador + checklist KMS de spec 01 + reconciliación `actualOutAtomic >= minOutAtomic`, con `EXECUTION_MODE=paper` como default; opcional, una proof de firma MCP en devnet iniciada desde la API. El diseño a live ya está hecho (PR #7); no es parte de esta fase |
| 1.2 — Onda MCP (BYOA) | ✅ Prendido en producción como demo interna (`MCP_ENABLED=true` en la app; código en v0.4.0 detrás de flag con default `false`, la séptima tool `onda_get_asset_info` read-only llegó en v0.5.0): servidor MCP Streamable HTTP stateless en `/mcp`, 7 tools sin tool de ejecución, API tokens por usuario (hash-only, scopes cerrados, 90 días) + Settings web, firma siempre en Onda. Connect manual probado end-to-end con un cliente MCP real: quote → propose → pending → slide-to-sign físico → ejecutado paper. Pendiente: dominio propio para onboarding público (Q-M3, owner Dino) y OAuth 2.1 (fase 1.3). H11 sigue abierto, por eso sigue siendo demo interna sobre la URL cruda de Azure. Spec: [07-onda-mcp.md](specs/07-onda-mcp.md) |

| 2 — Phantom Connect multi-usuario | Pendiente: embedded wallets por usuario, spending limits y verificación de acceso al Portal (DIN-39). Cruzar con H11 en [06](specs/06-roadmap-risks.md): la demo sigue interna hasta verificar la elegibilidad xStocks en Argentina |
